I feel like I learned to program twice, in different eras.

The first time, was in
[Applesoft BASIC](https://en.wikipedia.org/wiki/Applesoft_BASIC) on an Apple
IIGS. I remember my mom showed me the fundamentals, and I had a book with
code listings of games. I don't think I even had a proper language manual, so
there were some language features I didn't know about because I didn't see
them in the code listings in my book. Applesoft BASIC had an incredibly
primitive editor, where you would type in a line of code into the prompt and
then hit enter. Upon hitting enter, the line would be saved to the buffer.
How did the editor know where to insert that line? Because you prefixed the
line with the line number. To change a line, you simply insert a new line of
code at the same line. How do you insert a new line of code in between two
existing lines? The convention was to number consecutive lines by intervals of
10, so that you would have space to insert more code later. For example:

```BASIC
10 PRINT "THIS IS THE START"
15 PRINT "THIS WAS ADDED LATER..."
20 GOTO 10
```

In other words, I was using almost the most minimal development "environment"
possible. Looking at all the code at once required physically printing it out
to paper, debugging meant `PRINT` debugging, and there was no need for a build
system as there was no facility for importing external modules and every line
was interpreted right before being executed.

Once my parents upgraded to a Windows PC I bought my
first real programming book:
[C For Dummies](https://www.goodreads.com/en/book/show/3509477-c-for-dummies-volume-1).
That book explained to me for the first time the difference between a word
processor and a text editor. On Windows 98, I realized that Word was a word
processor and Notepad was a text editor. So my first editor for C was Notepad.
The only free compiler I could find at the time was a command-line Bloodshed
C++ compiler. I don't remember it coming with documentation, so I only knew
how to compile programs (didn't know about enabling warning flags). So my C
workflow consisted of writing code in C, running Bloodshed, getting a cryptic
compiler error and needing to circle back to Notepad, getting it to
compile, running it and getting a cryptic segfault, and going back to Notepad
and trying to guess why the code was wrong.
