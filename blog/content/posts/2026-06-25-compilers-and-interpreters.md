When I first learned about computers and programming languages, I learned that
there were two kinds of languages: compiled, which ran fast, had static types
(though I didn't know the term then), and were difficult to learn; and
interpreted, which were slow, dynamically typed (or even un-typed), and were
easy to learn.

Unfortunately, this overly simple dichotomy of programming
languages largely persists today, even though the reality is much
more nuanced and complicated.

## What is a Compiled Language?

First, what even is a compiled language? It seems obvious that C is a compiled
language. After all, once you write a program in C, you must call the compiler
in order to generate an executable binary before you can run it. Is Java a
compiled language? It has a compiler, and once you write your Java program, you
must call that compiler to generate a binary file. The nuance here, is that
your hardware CPU cannot directly execute that binary file, because it is
encoded in Java's bytecode. It must be *interpreted* at runtime by the Java
Virtual Machine (JVM).

And if we concede that Java is a compiled language, then why not Python? The
`python` binary contains a compiler that takes in Python source code and
generates bytecode (it will even write that generated bytecode to disk with
the `.pyc` extension), which then gets passed to the bytecode interpreter.

These distinctions are further muddied by the fact that many bytecode
runtimes (including the JVM) include a Just in Time (JIT) compiler, where
some or all of the bytecode will be compiled to native machine code to
improve performance.

And finally, when discussing languages in this section, I've been cheating by
really describing their most popular implementations. C, Java, and Python all
have multiple implementations. For example, [cython](https://cython.org) will
translate Python code to C code, which must then be compiled to machine code.
On the other hand, [picoc](https://gitlab.com/zsaleeba/picoc) is an interpreter
for (a subset of) C. Just because the most-used implementation of a language
uses an interpreter does not mean the language is inherently interpreted, or
could not be implemented as an ahead-of-time machine code compiler.

interpreting--they are not mutually exclusive. And many languages have multiple
